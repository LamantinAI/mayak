# Mayak 1.3.1

Патч по четырём находкам Astra, каждую из которых независимо подтвердил Fable. Три исправления
лежат в коде, который наследует проект, четвёртое — в инструменте шаблона. Форма ответов, вывод
просмотрщика трасс, настройки, цели `make`, схема и боевые миграции не меняются.

## Что изменилось

- **Одновременные проверки готовности делят одну пробу базы.** Второй запрос `/health/ready`,
  пришедший, пока шла проба того же пула, сразу получал 503 `Database check timed out`, хотя
  никто не ждал двух секунд: проверки оркестратора, балансировщика и мониторинга в одни
  30 мс выводили здоровую реплику из работы. Теперь срок принадлежит пробе: заставший её запрос
  ждёт ту же пробу до её срока и получает её вердикт и её `response_time_ms`. Отменённый
  HTTP-запрос больше не отменяет общую пробу — её отменяет таймер срока, даже если ждать
  некому. Проба, зависшая после срока (отмена драйвера не возвращается), как и раньше, сразу
  отвечает «timed out» и не даёт запустить вторую; после её завершения следующий запрос
  запускает новую. Кэша результатов нет, реестр — на процесс, как и был.
- **Извлечение не удаляет локальную работу.** План перечислял в каталогах шаблона
  (`TEMPLATE_ONLY`) только то, что отслеживает Git, а применение удаляло эти каталоги целиком:
  неотслеживаемый тест или заметка, добавленный в индекс файл и незакоммиченная правка
  исчезали, и ни `--dry-run`, ни bootstrap их не называли. Теперь один `git status` по этим
  путям решает до любой записи: неотслеживаемые файлы, правки в индексе и рабочем дереве и
  игнорируемые файлы, которые не являются отходами инструментов, называются поимённо в отказе
  «reference vertical kept: …» с выходом «закоммитьте, перенесите или удалите и запустите
  снова». Через тот же `build_plan` идут `--dry-run`, обычный запуск и предварительная проверка
  `make bootstrap` — она останавливается до записи файлов идентичности. Известные отходы
  (байт-код, `__pycache__`, кэши pytest, mypy и ruff) вносятся в план отдельным списком,
  `--dry-run` печатает их число одной добавленной строкой, а применение удаляет ровно
  запланированные файлы и затем опустевшие каталоги. Удалённый пользователем отслеживаемый файл
  причиной не считается; каталог без Git ведёт себя по-прежнему. Набор удаляемых путей тот же,
  флага принудительного удаления нет. Это сознательное изменение контракта: неотслеживаемый
  файл в каталоге шаблона теперь останавливает извлечение, а не исчезает.
- **Тест блокировки миграций проверяет ту базу, которую мигрировал.** Итоговая проверка
  подставляла имя пробной базы в текст DSN, но штатный построитель кладёт имя в `?dbname=`,
  замена ничего не меняла, и тест считал строки `alembic_version` в базе набора — она уже на
  голове независимо от того, мигрировал ли кто-то пробную базу. Теперь имя передаётся драйверу
  отдельным параметром, `current_database()` обязан назвать пробную базу, а набор ревизий в ней
  — совпасть с головами каталога миграций образа. Новый функциональный тест закрепляет
  читатель: пробная база, которую никто не мигрировал, не содержит ревизий. `alembic/env.py`,
  блокировка и миграции не менялись.
- **Показ всех трасс разбирает журнал один раз.** `format_all_traces_for_llm` для каждой трассы
  заново разбирал весь файл: строки × (трассы + 1) вызовов `json.loads` — 8 200 на 40 трасс по
  пять строк, вчетверо больше при удвоении. Это путь `make format-trace ARGS="<файл> --all"`,
  `make logs ARGS=--all` и сводки при остановке (`ENABLE_FULL_TRACE=true`), которой контейнер
  даёт 45 секунд. Теперь каждая строка разбирается один раз общим читателем `trace_tree`, события
  группируются по трассе в порядке строк, а рендер одной трассы и сбор её заголовка общие для
  обоих показов. Вывод побайтно совпадает с 1.3.0; событие начала запроса с нестроковым
  `trace_id` и JSON-строка, которая не является объектом, пропускаются, а не роняют показ.

## Проверка

| Исправление | На коде `v1.3.0` | На 1.3.1 |
|---|---|---|
| Готовность | 5 из 26 тестов файла красные: `[200, 503]`, `[200, 503, 503, 503, 503]`, 503 у присоединившегося, отмена пробы, «timed out» вместо «connection failed» | 26 зелёные |
| Извлечение | 8 красных: удаление заметок, правок, файла в индексе и игнорируемого пользовательского файла; план без отходов; bootstrap с кодом 0 | 23 зелёные; настоящий `make bootstrap` с заметкой: код 2, изменился только байт-код интерпретатора |
| Тест миграций | в Docker: старая проверка на немигрированной пробной базе читала базу набора и проходила; с чужой ревизией проходила; при Alembic, направленном в другую базу, проходила; у базы, названной как пользователь, подменяла пользователя | в Docker: оба теста зелёные; во всех четырёх случаях новая проверка красная |
| Трассы | `json.loads`: 8 200 при 200 строках, 32 400 при 400, 802 000 при 2 000 строк сводки; нестроковый `trace_id` — `TypeError` | не больше числа строк; 400 трасс через CLI — 3,42 с → 0,11 с при побайтно равном выводе |

Тесты на время не добавлены: регрессия трасс считает вызовы `json.loads` на фиксированных данных.

## Бюджет кода проекта

Посчитано `make check-product` (функция `count_python_lines`) из релиз-кандидата; оба профиля дают
одинаковый Python.

| дерево | строки кода | непустые строки (единица до 1.3.0) |
|---|---|---|
| проект из 1.3.0, оба профиля | 17 971 | 22 034 |
| проект из 1.3.1, оба профиля | 18 158 (лимит 18 500, запас 342) | 22 250 |
| шаблон 1.3.1 | 25 401 | 30 689 |

Релиз добавляет проекту 187 строк кода, почти все — регрессионные тесты готовности и трасс в
`tests/application`; тесты извлечения лежат в `tests/template` и в проект не попадают. Лимит
по-прежнему действует: `--limit 18157` на проекте из 1.3.1 даёт
`FAIL: a project made from this template carries 18158 lines of code, over 18157`.

## Что не изменилось

- Ключи, сообщения и коды ответа `/health/ready`, поле `timeout_seconds`, скрытие текста ошибки.
- Боевой Alembic, блокировка миграций, схема и настройки.
- Набор путей, которые удаляет извлечение, проверки образца и вырезок, повторный запуск —
  «already done».
- Вывод просмотрщика трасс и его CLI, сводка при остановке и её формат.

## Обновление существующего сервиса

Раздел [«Porting the 1.3.1 changes»](../upgrades.md#porting-the-131-changes) руководства по
обновлению. Сервис наследует три исправления: `health.py`, два файла просмотрщика трасс и
функциональный тест миграций — каждый файл берётся целиком, если сервис его не менял. Защита
извлечения живёт в инструменте шаблона, которого в сервисе уже нет.
