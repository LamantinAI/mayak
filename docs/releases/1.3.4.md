# Mayak 1.3.4

Патч добавляет ранний read-only preflight Alembic-графа и эффективной конфигурации PostgreSQL в полный `make verify` сразу после вывода `verify: scope:` и до запуска дорогих этапов (`quality-gates`, маршрутного/diff-покрытия и Docker E2E).

## Что изменилось

- **Ранний read-only preflight в `scripts/verify_change.py` и `scripts/validate_migrations.py`.**
  - После печати `verify: scope:` полный `make verify` вызывает общий read-only `collect_migration_precheck_issues(Path.cwd(), require_database=True)` до запуска `make quality-gates`.
  - Сначала выполняется offline-проверка графа ревизий Alembic (`migrations.multiple_heads`, `migrations.broken_revision_graph`) без подключения к БД — ошибки графа имеют приоритет даже при недоступной БД или `POSTGRES_ENABLED=false`.
  - При `POSTGRES_ENABLED=false` (`DB=none`) и при `--coverage-only` (`make diff-coverage-report`) новые подключения к PostgreSQL не открываются.
  - При `POSTGRES_ENABLED=true` полный `make verify` проверяет доступность БД и для diff, затрагивающего только тесты или документацию; при отказе выводит точную причину и команду следующего шага (`verify: preflight: FAIL (<rule_id>)` и `verify: FAIL — migration preflight`) без запуска дорогих стадий.
  - Preflight не выполняет автоподготовку БД, DDL или миграции; фактические `alembic upgrade head` и `alembic check` по-прежнему выполняются один раз в полном валидаторе внутри `make quality-gates`, сохраняя обработку позднего отказа и применимости.

- **Эффективная конфигурация PostgreSQL и различение причин.**
  - Незаданная локальная конфигурация без `.env` и без `POSTGRES_*` в окружении не ждёт TCP-таймаута и предлагает `make init-project`, затем `make db-up-worktree`.
  - Локальный checkout с `.env` на loopback-хосте без поднятой БД предлагает `make db-up-worktree`.
  - Явно заданная недоступная цель (`POSTGRES_*` в окружении, non-loopback `POSTGRES_HOST` в `.env`) или `CI=true` указывает на целевую БД задачи без совета запускать `make db-up-worktree`.
  - Валидная целевая БД через `POSTGRES_*` в окружении без файла `.env` (включая частичное переопределение без `POSTGRES_USER`) и `CI=true` без `.env` при уже слушающей БД корректно проходят preflight и валидацию.
  - Повреждённый `.mayak-postgres-port` или невалидная конфигурация `POSTGRES_*` завершаются диагностикой без трассировки и без вывода значений секретов.

- **Граница изменений.**
  - Контракты `/health/ready`, `entrypoint.sh`, `bootstrap` и HTTP API не изменялись.
